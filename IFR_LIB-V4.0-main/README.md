# IFR_LIB-V4.0
伟大的IFR库，v4.0版，增加队列等重大更新，支持DJI、DM、RS三家电机的统一数据接口，所有消息统一发送等

1、CAN库、电机库全部重构

增加ifr_basic_motor电机基类，所有电机类继承于这个电机类，使用多态语法，实现函数重载和接口统一。同时删除大量冗余代码，实现将重复代码统一使用函数来解决。

增加ifr_can_msg_queue.h，针对CAN做的队列系统，将所有CAN消息统一结构为CanMsg。电机类发送消息时将消息入队，在CAN统一发送时出队再发送，以实现将DJI的一拖四、DM的MIT、RS的拓展帧协议的统一。

同时大大增加拓展性，未来若出现RS等厂家新的型号，则可以直接在RS库中添加新的枚举和对应的各项电机参数，不会再出现之前的多款电机用同一个参数的情况。

未来若出现新的电机协议，则直接继承于ifr_basic_motor电机基类，并将电机类使用CanMsg消息结构入队即可，不再需要动CAN类、队列类、电机基类，只需要添加新的电机类，使用相同接口即可，让CAN回归通信方式，而不再将CAN类和电机类做强绑定。

CAN库中除了可以注册8个ifr_basic_motor电机以外，可以注册四个自定义CAN接收处理函数，并且可以通过调用CAN_Transmit发送单个消息，若此时无法发送（邮箱满）则消息会进入队列存储再发送。


2、修改remote.c和串口库

删除之前remote冗余的键盘按键检测等代码，增加新遥控器（VT13）的适配

增加串口库的发送缓冲队列ifr_usart_queue.h，类似CAN库，同时将双缓存机制更换为环形缓存区，增加缓存区大小（可以通过宏定义设定大小）


3、增加状态机和按键库

增加一个ifr_state_machine库，可以定义状态变量和对应状态变量进入、持续、退出时的事件，通过函数指针传入事件（没有则设定为NULL）

增加一个ifr_key库，调用时传入一个状态量，可以指定这个状态量的上升沿、下降沿、双边沿、长按时执行的事件（可以同时适用），自带防抖检测（可以设定防抖次数），长按模式可以设定单次还是持续执行，可以设定长按的次数量是多少，
并专门特化一个函数用来直接指定另一个变量的变化的值

4、增加额外库ifr_extra，提供变量最小最大值限制函数、半圈判断函数

以下是IFR库架构：请详细阅读，目前这样的架构已经实现：

分层清晰：各层职责明确，便于团队协作开发

松耦合：层间通过标准接口通信，降低依赖

高内聚：每层专注于特定领域的逻辑

易测试：可逐层进行单元测试和集成测试

可维护：问题定位和代码修改范围明确

可扩展：新功能可在适当层级独立添加
